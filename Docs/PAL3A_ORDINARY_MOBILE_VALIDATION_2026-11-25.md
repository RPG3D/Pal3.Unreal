## 项目打包参数修正

首次 Cook 读取到历史审查留下的损坏 UAT 生成记录，内容还指向 Saved 内的旧插件备份。移除该记录后，Cook 子进程找不到 BuildUserSolution，进一步暴露准备入口缺少项目脚本上下文的问题。

ModulePublisher 的标准 UAT 调用补传 `-ScriptsForProject`，同时保留精确的插件 `-ScriptDir`。清理本机两处历史生成记录后，从无记录状态执行准备，得到指向当前插件的项目根构建记录；随后 Android、iOS 的 Cook 均成功，实际执行了普通 C# 构建。没有增加运行时清单或插件加载策略。

Mac 独立 Game 编译在确认不属于交付前置后取消；实际移动目标均完整编译。Cook 沿用已验证的本地 CookOutputDir 与 SkipZenStore，iOS 沿用当前引擎所需的可选 UGP 链接参数。

## 真机结果

通过项目既有文件自动化命令驱动真实游戏会话，并保留游戏选择界面与游戏画面截图。

| 范围 | Android 真机 | iPad Air M3 |
|---|---|---|
| 两游戏启动与跨进程切换 | 通过 | 通过，最后再次切回问情篇 |
| 目录读取 | Download/PAL3、Download/PAL3A | 原有 PAL3、PAL3A 授权直接复用，无路径覆盖参数或重新授权 |
| 场景 | 仙剑三 4 个、问情篇 3 个 | 相同 7 个 |
| 镜头与 GC | 可旋转地图实际旋转、主动 UE GC 通过 | 实际旋转、主动 UE GC 通过；读档后镜头权限保持一致 |
| 存读档 | 99 号临时槽保存、进程内及冷启动读档通过 | 相同检查通过；每游戏冷启动后 10 次静置坐标与保存值一致 |
| 用户数据保护 | 3 份原存档哈希一致 | 9 份原存档哈希一致，两份目录 bookmark 保留 |

场景覆盖仙剑三渝州、客栈、宾化、镇江，以及问情篇唐家堡登云麓、蜀山回家、绿萝嶂。镇江冷启动读档后坐标稳定，镜头可旋转，截图保留右摇杆。临时槽已移除，原游戏选择已恢复；收尾以不带自动启动参数的方式启动应用，前台显示以用户当前操作为准。

iPad 两游戏玩法检查通过后，devicectl 在收集最后日志时出现连接超时，并中断首次清理。已通过原生设备服务恢复连接，停止测试进程，恢复并核对全部原存档、移除临时槽，再次启动问情篇验证授权并复核数据。该连接错误没有被当作游戏崩溃，也没有直接覆盖为成功结果；失败和恢复记录均保留。

## 内存与边界

- Android 最大采样 PSS 1073 MiB、RSS 1249 MiB。
- iPad 最大采样 physical footprint 1154 MiB、resident size 1122 MiB。
- Cook 编辑器最大采样 RSS 2089 MiB；12 GiB 保护未触发，编辑器进程均已退出。

上述指标含义不同，不作平台直接对比。短时切图、GC 和静置期间未见持续失控增长，不代表已排除长时间游玩的慢性泄漏。本轮没有复现历史 Trace 启动崩溃，相关引擎问题仍按原记录保留。

本轮没有覆盖移动 CoreCLR、Shipping/R8、所有地图及完整剧情通关，没有启动模拟器。iOS 仅验证当前 27.2.1 真机；链接器提示 SDK 的 CoreLib 静态对象最低版本为 26.5，高于工程声明的 17.0，因此不据本轮结果宣称旧版 iOS 兼容性已验证。
